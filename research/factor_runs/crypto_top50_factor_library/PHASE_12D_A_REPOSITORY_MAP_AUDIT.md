## Part C — Source-of-Truth Rules

### Rule 1: `research/factor_runs/crypto_top50_factor_library/` is the audit dossier
This folder is the **primary audit dossier** for the current research run. It contains:
- Phase plans and closeout reports (human-authored, source of truth)
- Generated CSV/Parquet evaluation outputs (generated, reproducible)
- Alphalens exports (generated, reproducible)

**Do not edit generated CSVs manually.** Re-run the pipeline to regenerate.

### Rule 2: `docs/factor_library_transparency/` is the human-readable transparency source
This folder contains Phase 12C transparency documentation. These are **human-readable summaries** of the research dossier. They are source-of-truth for the PM's understanding but should be kept in sync with the research dossier.

### Rule 3: `reports/site/factor-library/` is generated website output
This folder is the **generated website output** and should **never be the only source of truth**. All content here should be derivable from the research dossier and transparency docs. If this folder is lost, regenerate from source.

### Rule 4: `scripts/` contains reproducible generation logic
All data generation, evaluation, audit, and website publishing logic lives here. Scripts are the **reproducibility guarantee** — given the same inputs, they produce the same outputs.

### Rule 5: `src/momentum/` contains reusable package code
The core Python package for factor computation, signals, risk, and execution. Changes here affect all downstream outputs. Code review required for changes.

### Rule 6: `data/` contains generated or cached data
Factor values, labels, universe membership, and market data caches. **Do not manually edit.** Regenerate by running the pipeline scripts.

### Rule 7: `tests/` protect logic and assumptions
Test files verify that factor computation, evaluation, and pipeline logic remain correct. **Always run tests before committing changes** to `src/` or `scripts/`.
