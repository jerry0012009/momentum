# Rank 101 park reframe review

- 时间：2026-03-25 04:57 UTC
- 对象：`Rank 101 / 3-step volume dry-down long-bias gate`
- 原始结论：`park / evidence pool`
- 本轮结论：`soft_reframe_candidate`
- 是否保留原 park 审计意义：`是`

## 为什么这次看 Rank 101
- 按 `PARK_REFRAME_QUEUE` 当前轮转，`50~79` 号段本日已覆盖到 `Rank 67`，本轮切到 `80~110` 号段。
- 最近 7 天的 `research/park_reframe/INDEX.md` 未见对 `Rank 101` 的 park-reframe 复盘记录，符合“优先换别的”原则。
- 这条线已经有明确 `park` 审计结论，但它留下了一种容易被误判成“还能救活 standalone gate”的残余叙事：缩量回踩在 long side 确实有 pocket，因此值得单独确认这到底够不够长出一个新的窄派生假设。

## 原 rank 为什么 park
基于 `research/optimization_loop/2026-03-19_2233_rank101-volume-drydown-clean-replication.md`：
- 原假设是把 `3-step volume dry-down + low-volume budget` 写成一条可审计的 `long-bias gate`，希望它能给 `Fib retest / EMA continuation` 提供更干净的 hold-quality 过滤，并顺带检查 short 镜像是否也成立。
- 最好看的组合臂是 `dv3_lv80`：
  - `long baseline ≈ -11.71bps`
  - `long dv3_lv80 ≈ +0.12bps`
  - `win_rate ≈ 48.15%`
  - `positive_asset_ratio ≈ 66.67%`
- 但这个改善几乎完全靠**极端砍样本**换来：
  - `retention_vs_baseline ≈ 3.41%`
  - 实际只剩 `54` 笔 long 样本
- 跨资产也不统一：
  - `ETH ≈ +20.53bps`
  - `SOL ≈ +1.67bps`
  - `BTC ≈ -22.89bps`
- short 镜像更差：`short dv3_lv80 ≈ -24.71bps`，明显不能被诚实包装成 breakout-short 的 shared admission。
- 所以原始 `park` 的含义不是“缩量回踩完全没信息”，而是：**把它写成 standalone、可广泛复用的 hard gate 不诚实；它更像局部 long-side hold-quality 线索。**

## 它更像 hard park 还是 soft park
**结论：soft park。**

原因：
- 它不是 hard park，因为 long side 的 pocket 不是幻觉，`dv3_lv80` 至少把全负读法拉到 `2/3` 资产转正，说明“回踩时参与度衰减”这件事有局部解释力。
- 但它也离“可直接 draft 新 rank”还有明显距离：
  - 样本太稀；
  - `BTC` 仍负；
  - short 侧镜像直接失败。
- 更准确地说，它像一条**有残余信息、但尚未压缩成诚实单轴新队列项**的 soft park。

## 有没有可救信号
**有。** 主要是两条：
1. `dry-down + low-volume` 在 long side 确实优于 baseline 与 `low-volume-only`，说明有效信息更接近“缩量吸收完成”，而不是泛泛“低量就好”；
2. short 镜像显著变差，反而把职责边界说清楚了：这主题更像 **Fib retest / EMA continuation 的 long-side hold-quality note**，不是 shared trigger，更不是 short confirm。

但这些可救信号目前仍不够支撑新的 derived hypothesis，原因也同样明确：
- 当前 pocket 太窄，仍主要像切样本；
- 最自然的下一刀其实是**放松稀疏度**，而不是再起一个完整新 rank；
- 若直接 draft `Rank 101b`，很容易把“long-side hold-quality note”误包装成“可排队的独立 gate 候选”。

## 最值得改的唯一一刀是什么
如果只保留唯一主修改轴，最值得改的是：

**把 `3-step dry-down + lv80` 从 standalone hard gate，降级成 `Fib retest / EMA continuation` 的 pre-reclaim long-side hold-quality note，并优先测试更松的样本保留写法，而不是继续坚持当前极窄 `dv3_lv80` 组合。**

为什么是这一刀：
- 原始证据已经说明“单纯 low-volume 不够”，真正有信息的是 `dry-down`；
- 同时又说明把它写成当前 strict 组合门槛会把样本砍得过狠；
- 所以最自然的收缩方向不是“再镜像到 short / 再扩成 shared gate”，而是**只保留 long-side hold-quality 角色，并先解决 retention 过低这个 blocker**。

## 是否值得形成新的 derived hypothesis
**当前不值得，先停在 `soft_reframe_candidate`。**

原因：
- 原 `park` blocker 还没被消化掉：`+0.12bps` 配 `3.41%` retention，离可诚实入队仍太远；
- 现在最像“下一步”的仍是一个实现松紧问题，而不是一个足够独立的新 hypothesis；
- 最近新增的相关证据并没有把这条主题升级成新的 raw-alpha family，仍只是补强它作为 long-side hold-quality note 的角色边界。

换句话说：**Rank 101 有可救信号，但更像“值得记住的 residual note”，还不像 bot2 应该直接认领的新提案。**

## 本轮最终结论
- `final_status = soft_reframe_candidate`
- `original verdict kept = park`
- 简述：`Rank 101` 应保留为一条“缩量回踩在 long side 有局部吸收语义，但当前 strict dv3_lv80 写法主要靠极窄 retention 美化”的审计案例；残余价值暂时只够停在 `soft_reframe_candidate`，不诚实直接 draft `Rank 101b`。
