7. Signal Evaluation Framework：信号评价框架

本节解释当前信号不是只靠一个回测结果判断，而是通过 RankIC、分组收益、尾部诊断、变体网格、成本/流动性桥接等维度逐层筛查。

当前 10A/10B/10C/10D 是研究推进过程中的阶段脚本，不是最终模块化框架。它们的评价逻辑可以复用，但脚本接口还需要抽象成 signal-agnostic evaluator。未来无论信号来自人工因子组合、线性模型、机器学习模型还是 ensemble，只要输出统一的 signal panel：timestamp / symbol / signal_name / signal_value，就应能复用同一套评价框架。

7.1 当前信号评价维度

评价维度目的计算方式当前结果（core_only）脚本可复用
RankIC / 横截面排序预测力 判断信号排序和未来收益排序是否相关 对每个 timestamp，计算 signal_value 与 future_return 的 Spearman correlation。
RankIC_{h,t} = SpearmanCorr(rank(signal_t), rank(forward_return_{t→t+h}))		 1h=0.0325(t=17.6) · 4h=0.0385(t=20.8) · 24h=0.0416(t=22.6) · 72h=0.0338(t=18.1)
RankIC 为正且 t-stat 高，说明有横截面排序信息；但不等于可交易收益		 run_phase10a_signal_backtest.py YES
Quantile Spread / 分组收益 判断高分组和低分组的未来收益差 按 signal_value 分桶，计算 top bucket 与 bottom bucket 的 forward return 均值差。
spread_h = mean(return | top) - mean(return | bottom)		 core_only mean spread: 1h=-0.000306 · 4h=-0.001232 · 24h=-0.006742 · 72h=-0.016623
⚠️ RankIC 为正但 mean spread 为负，说明存在 bucket/tail 异常		 run_phase10a_signal_backtest.py YES
Direction / Quantile Consistency 检查 RankIC 方向、bucket 排序和 long-short spread 是否一致 对比 RankIC 符号与 top-bottom spread 符号 RankIC 正，但 top-bottom mean spread 负，方向冲突 run_phase10a_r_diagnostics.py YES（应做成通用 consistency checker）
Bucket / Tail Diagnostics 检查极端 bucket 是否支配均值结果 检查 bucket0、median spread、winsorized spread、tail-trimmed spread、bucket monotonicity bucket0 / tail behavior 对 mean spread 影响很大；median spread 与 mean spread 方向可能不同。详见 Phase 10B outputs。 run_phase10b_tail_diagnostics.py YES
Tail-aware Policy Design 设计是否需要 bucket0 guard、方向翻转、tail-aware 规则 不是标准评价指标，而是对当前信号异常的设计响应 基于 10B 输出设计 guard / direction policy Phase 10C（如无独立脚本，标记为文档/设计阶段） PARTIAL（概念可复用，策略应针对每个信号重新设计）
Variant Grid / 信号变体网格评估 比较不同 signal variant × horizon × guard × direction policy 的 pass/fail 网格遍历所有变体组合，产出 pass/fail matrix 当前核心纸面信号为 signal_v0_core_only__1h__original_no_guard。详见 phase10d_variant_pass_fail_matrix.csv。 run_phase10d_tail_aware_variants.py YES（需参数化成 generic variant grid evaluator）
Cost / Liquidity Bridge 把 gross signal evaluation 接到成本、滑点、容量诊断 不是 10A-10D 的一部分，但决定信号能否进入 paper diagnostic 成本/滑点诊断通过，core_only 扣除成本后仍保持 spread run_phase11a_cost_slippage_capacity.py YES（未来信号也必须通过）

7.3 如果未来信号来自机器学习模型，如何复用评价框架？

可以复用的前提：ML 模型输出统一 signal panel：
timestamp / symbol / signal_name / signal_value / optional(model_version, feature_set, training_window)

只要满足这个接口，就可以复用：RankIC、quantile spread、direction consistency、bucket/tail diagnostics、variant grid、cost/liquidity bridge、paper monitoring。
不能直接复用的部分：
  • 当前 build_phase9b_signal_panel.py 里的固定三信号构造逻辑
  • 10C 针对当前信号 tail 问题设计的特定 policy
  • 任何硬编码当前 signal names / current run paths 的脚本

7.4 当前代码结构判断

当前 10A/10B/10D 脚本可以完成本轮研究任务，但长期来看阶段化命名较重，接口不够通用。建议后续重构为 signal-agnostic evaluation package，把当前阶段脚本改成 wrappers。

建议结构：
src/momentum/signal_evaluation/ — metrics.py, rank_ic.py, quantile_spread.py, bucket_diagnostics.py, tail_diagnostics.py, variant_grid.py, cost_bridge.py, report_schema.py
scripts/ — run_signal_evaluation.py, run_signal_variant_grid.py

7.5 当前信号评价结论摘要

当前核心信号 signal_v0_core_only 在 RankIC 上显著为正，但 mean quantile spread 为负，说明它不是一个已经干净验证的 alpha。后续 tail diagnostics、variant grid、cost/liquidity、paper diagnostic 是为了判断它是否值得继续观察，而不是证明它已经可以交易。
