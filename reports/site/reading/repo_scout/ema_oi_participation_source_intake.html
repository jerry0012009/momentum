为什么这轮轮到它

  • EMA 当前仍是 running paper / waiting_not_due，不是 due-now refresh 窗口。
  • Rank 17 / 2 / 29 / 32b 这些 P3 lane 继续由专属 refresh / monitoring 托管，没有新的 append/review 状态变化。
  • Rank 43、Rank 40、BotScalpingTwinRange、Rank 27b、FibTrend-Pro 都已在允许预算内给出 hard verdict 并压回 park。
  • 和 EMA-ADX-VOL skeleton 相比，OI participation gate 是更窄的一条新轴：它不重写 entry，只先回答 低参与度 whipsaw 能不能被便宜地砍掉。而且 Binance 公共 OI 接口直接支持 15m，更容易拿到诚实的最小 replication verdict。

两条轻量诚实守门

  • trade on：方向仍由 EMA 9/15（或后续复用 EMA / PSAR baseline）负责；只有当 OI > SMA20(OI) 时，才把当前 15m 动作当成值得执行 / 加权的信号。
  • trade off：EMA 方向未成立，或 OI 未高于自身短均值，则不交易 / 不加权；若后续最小 replication 证明 trade count 被砍到失真，或 whipsaw 并未改善，也应快速压回 park。
  • lookahead / repaint / leakage 读法：repo 里 buy / sell 共用同一个 OI 条件，说明它过滤的是 participation 而不是方向预测；当前未见一眼可判死刑的未来函数。但 replication 必须把 true OI 与 volume fallback 拆成不同 bucket，不能混算。

为什么它当前高于 EMA-ADX-VOL skeleton

OI gate只新增一条 participation 轴，问题更窄：能不能在不大幅砍掉 trade count 的前提下压低 2~4 bar whipsaw。
EMA-ADX-VOL skeleton一次叠了 ADX / volume / range 三层 veto，更容易出现“强过滤换少交易”的假改善；它仍值得做，但不如 OI gate 更快给出诚实结论。
当前 desk 含义这轮更像先回答“参与度 gate 值不值得留”，下一轮再决定要不要继续给更厚的 EMA-ADX-VOL skeleton 预算。

下一轮只允许做什么

  • 固定 BTC / ETH / SOL perpetual，先用最近 30d~60d 的 15m 数据。
  • 统一冻结成 next-bar open + no-overlap。
  • 先比较四个最小臂：raw EMA(or EMA+PSAR)、+oi_level_gate、+oi_level_gate+oi_delta_gate、+volume_fallback_gate。
  • 先回答四个便宜问题：4/8/12 bar follow-through、2~4 bar whipsaw ratio、net expectancy @ 6/10bps、trade_count retention。
  • 默认不允许：一上来扩成长窗 OOS、大而全 OI 框架、或同时再开第二条 fresh intake。
