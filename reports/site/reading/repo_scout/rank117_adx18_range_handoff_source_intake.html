  • 这正好服务当前桌面主线：避免把 skip / size-down 误读成“自动反手开 range 单”。

这条线到底在说什么

repo 里的最小骨架很简单：

  1. 1H ADX(14) < 18，先把环境判成区间市；
  2. 15m BB(20,2) + RSI(14) 找极值；
  3. 下一根 candle 给反转确认；
  4. 问题是：这能不能从“别追趋势”升级成“值得共享给三条主线的反手 handoff”。

翻成人话：别追，和 反手做回归，不是同一件事。

两条轻量诚实守门

  • trade on：若它成立，也只能当 anti-chop veto 之后的候选 handoff；不能把 ADX<18 单独偷渡成新 alpha，更不能在没有 base context 时自动反手。
  • trade off：若 ADX<18 + BB/RSI extreme + next-candle confirm 仍无法给出稳定的成本后 mean-reversion expectancy，就必须停在 skip / size-down，不能升级成 shared range module。
  • lookahead / leakage：ADX、BB、RSI 与 next-candle confirm 都必须只用当根及之前已完成 bar；若要接到 desk，执行口径仍必须冻结为 signal 当根及之前数据 + next-bar open + no-overlap，不能用 4~8 bar 后是否真回中轨来反填入场标签。

为什么这轮直接 park

核心证据range_adx<18 事件池里，4-bar mean-reversion signed return ≈ -5.43bps；同一批事件的 continuation proxy 反而约 +5.43bps。
命中率以 BB 中轨当最小 TP1 代理，4 bars 内 hit 仅约 11.9%，8 bars 内约 20.0%；略好于 trend bucket，但远不够支持 shared handoff。
跨资产稳定性BTC≈-0.75bps 接近打平，但 ETH≈-10.40bps、SOL≈-4.96bps；更像 BTC-specific 可疑旁支，不像三线共享模块。
当前最诚实结论park / evidence pool。保留为“ADX<18 只能先当 skip / size-down 提醒”的反例证据，不再占 active Scout 主资源位。

它对 desk 的真实价值

  • 给 breakout-short：low-ADX 可以继续当“不追”的负面 gate，但不要误写成“被 veto 后自动改做 fade”。
  • 给 Fib retest_hold：sideways 也不等于自动回中枢，还是应该保留 hold / invalidate / timeout 的结构判决。
  • 给 EMA / PSAR raw alpha：避免本体 edge 还没坐实，就先长出一套“趋势不行时切回归”的并行系统。

下一轮不该继续做什么

  • 不要继续围着 ADX 18、RSI 30/70、BB 20,2 做无尽微调。
  • 不要把它继续写成新的 active Scout 候选。
  • 若后续还想保留反转旁支，只能另开更苛刻的 conditioned handoff（例如事件窗排除、same-clock RVOL 干燥确认、outside→back-inside 结构先验），不能把这一版直接续命。
