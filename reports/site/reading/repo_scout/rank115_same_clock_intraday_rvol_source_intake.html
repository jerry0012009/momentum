这条线到底在说什么

它真正值得偷的不是 repo 里的股票 breakout 参数，而是一个很朴素但经常被忽略的 volume 口径：

  1. 先把每根 bar 映射到自己的 HH:MM 时刻；
  2. 当前 bar 的 volume 只和历史同一个 HH:MM 的 bar 比；
  3. 不再用简单的 rolling 20-bar mean 把整条日内季节性压扁；
  4. 于是 slot_spike / slot_dry 更像在测“相对该时段是否异常”，而不是“UTC 活跃时段是不是天生更热闹”。

翻成人话：别把 14:30 UTC 的天然热闹误当成放量确认，也别把冷时段里的正常低量误当成优质 dry-down。

两条轻量诚实守门

  • trade on：它只能作为现有 setup 的 volume confirmation / dry-down layer。可挂到 breakout-short follow-up、Fib retest_hold、EMA/PSAR volume gate，但都只能先做 shared confirmation layer，不能自己单独开一条新策略。
  • trade off：没有 base setup 时不能单独开仓；如果 same-clock RVOL 只是在统计上重命名 UTC 活跃时段，却没有换来更低的 false-follow / false-hold 或更诚实的成本后 expectancy，就应直接 park。
  • lookahead / leakage：slot_rvol 只能用 signal 当根及之前、同 symbol、同 HH:MM 的历史已完成 bar 构造；clean replication 强制 next-bar open + no-overlap，禁止同 bar 判定后按同 bar 成交；阈值与 lookback 只能在训练段冻结，再去测试段验证。
  • 事件窗例外必须如实写出：若 FOMC / jump / 极端新闻把同 slot baseline 打穿，后续必须把该窗口当 blackout 或单独风控，而不是硬说“same-clock 已经解决一切”。

为什么它现在配拿 1 次最小 clean replication 预算

对当前 desk 的价值它不是又加一个新 filter，而是先把三条主线正在反复使用的 volume gate 计量口径修正得更诚实。
已有快检证据在 BTCUSDT 15m 最近样本上，same-clock 与 naive RVOL 对 spike / dry-down 的判定并不只是换皮：相关系数约 0.765，而 dry-down 冲突明显更大，足以说明它可能真实改变 follow-up / hold 判决。
当前最诚实结论guard-passed / admit_to_clean_replication_queue。也就是：值得拿 1 次最小 replication 预算，但还只是 shared volume gate 候选，不是 paper candidate，更不是 live challenger。

下一轮只允许做什么

  • 固定复用 BTC / ETH / SOL 120d 15m 本地 cache，不新开重型下载。
  • 只挂 1 条 base archetype（优先 Fib retest_hold 或 breakout-short）。
  • 训练段先冻结 N=20、slot_spike>1.5、slot_dry<0.7 或最小邻域；测试段统一 next-bar open + no-overlap。
  • 只比较 baseline_naive_rvol vs slot_rvol_gate，主看 post-cost expectancy、trade_retention、false-follow / false-hold、以及 same-clock 与 naive 的冲突是否真的对应更诚实的过滤。
  • 若改善主要来自砍样本、没有更诚实的成本后 uplift，就直接 park；若至少 2 个 symbol 上同时降低 false-follow/false-hold 且 retention 没塌，再考虑 keep_P1 / 升到 P2。
