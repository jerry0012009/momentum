方案一句话

研究侧证明 Rank29 在 10–15bps/side 下仍有 edge；这条 shadow runner 则把它切换到 Binance USDT-M perp 的真实盘口环境，用 L2 depth 逐档吃单 模拟成交，回答“如果以后 tiny-live，上哪些币、按什么方式进出，会不会被订单簿打穿”。

venue = binance_um_perphold = 8 x 15mfee = 5.0 bps/sidemax concurrent = 3

它和 gate shadow 不是一回事

  • 这页回答的是执行问题：真实盘口的 spread / impact / rejection 会不会把策略打穿。
  • 它不是 manual narrow paper 里的 gate shadow：后者是在 Binance spot 15m 的同一批 paper trades 上做 low_trend_high_noise_w25 降仓记账。
  • 这页会记录：L2 depth、VWAP、spread_bps、impact_bps、拒单原因、perp fee。
  • 这页不会回答：坏环境该不该降仓；那是 regime gate backtest / gate shadow 的职责。

如果你想看 Rank29 各条线的关系图，请回主报告页或读仓库文档 docs/RANK29_SHADOWS.md。

入场 / 离场规则

  • 信号来源： 对每个币抓 Binance UM perp 的已完成 15m bars，跑 trendline_breakout_navigator。
  • 开仓前置条件： bar 被标为 breakout_bull 且 composite_trend >= +2，或 breakout_bear 且 composite_trend <= -2。
  • 入场时点： 信号 bar 收完后，等 0 分钟到下一根 15m 开盘附近；如果超过 None 分钟仍没执行，则放弃本次信号。
  • 成交模拟： 用当时的 20 档深度，按目标 base qty 逐档吃单，得到真实的 shadow VWAP、spread_bps 和 impact_bps。
  • 拒单条件： 入场时如果 spread_bps > 8.0 或 impact_bps > 6.0，就拒绝这笔信号，不强行追。
  • 平仓原则： 固定持有 8 根 15m bar，到点后用相反方向的盘口深度逐档成交并计入实际退出滑点。
  • no-overlap： 每个币同一时间只允许 1 个仓位；全局最多同时 3 个仓位。
