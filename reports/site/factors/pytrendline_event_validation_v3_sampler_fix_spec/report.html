这页完成了什么？ 把 TODO 里的 A4-b 从一句很大的“修 sampler”拆成更小、可执行的 repair spec。 这页的目标不是宣称已经修好，而是先把 该修什么、为什么修、修完要看什么 写清楚。
一句话结论： 当前最合理的最小修法不是把全部 breakout 样本一刀切删掉，而是：保留 snapshot 可见性门槛，新增 event-time strict wrong-side filter，再单独处理 exact mirrored breakout pairs。

1. 这轮发现了什么？

  • Found: purged 样本里 breakout 仍有一批严格几何异常，不是 100%，但也不是可以忽略的小噪声：
    • support_breakout_raw strict wrong-side share = 18.8%（9/48）
    • resistance_breakout_raw strict wrong-side share = 22.0%（11/50）
    • support_breakout_confirm_1 = 23.4%；resistance_breakout_confirm_1 = 18.0%
    • support_breakout_confirm_2 = 23.9%；resistance_breakout_confirm_2 = 18.0%
  • Found: purged breakout 三个 family 各还留着 1 条 exact mirrored pair，而且 pair-level geometry 仍然是彻底异常：crossed_lines_share = 100%、both_inverted_share = 100%。
  • Found: 当前 sampler 源码里已经能检测到 snapshot 时刻的 side 可见性门槛（support 不应早已高于价格，resistance 不应早已低于价格）。说明下一步修法应继续往 更晚一层的 event-time / pair-time 清洗 补，而不是推翻已有全部逻辑。

2. 这轮没有发现什么？

  • Not found: 没有证据支持“全部 breakout 行都坏了”。上一轮最刺眼的 100% close-based 指标，主要是在重复 breakout 定义本身。
  • Not found: 还没有修完后的最小重跑，因此这页不回答“修完后 breakout family 还剩多少 alpha”。
  • Not found: 当前 purged 样本里没有观察到“support / resistance 两边都严格几何合法、却还 exact mirrored”的 clean case，所以若未来两边都存活，临时 tie-break 只能先视为低置信 fallback。

3. 建议的最小 repair rules

rule_id title scope action why current_status reliability
R1 Keep the snapshot-side visibility guard as the first screen All future breakout/touch candidates Reject lines that are already on the wrong side at snapshot time before generating any event rows. This is the earliest causal checkpoint: if a support line is already above price (or resistance already below price) when the snapshot becomes visible, later event labels are hard to interpret. present_in_sampler_code high for code detection; medium for downstream impact
R2 Drop strict wrong-side breakout rows at event time support/resistance breakout raw + confirm families For support-side breakout rows, drop if line_value_event > event_high. For resistance-side breakout rows, drop if line_value_event < event_low. These rows are not merely close-based breakouts; the entire event candle already sits on the wrong side of the labeled line, so the side tag is geometrically unreliable. design_fixed_here_not_implemented_here high for identifying bad rows; medium for how much alpha changes after rerun
R3 Resolve exact mirrored breakout pairs after row-level filtering Rows sharing symbol + family + event/confirm/action timestamps across support/resistance If only one side survives R2, keep that side. If both sides fail, drop both. If both sides survive, keep the higher-score row only as a temporary tie-break and mark it ambiguous in audit output. The remaining mirrored rows are the clearest source of duplicated family returns. They should be handled explicitly instead of hoping the top-score-per-event_type rule removes them. design_fixed_here_not_implemented_here high that mirrored pairs exist; low-to-medium for the tie-break branch because this sample does not yet contain a clean surviving pair
R4 Judge success by rerun audits, not by hope BTC+ETH / 20d-45d minimal rerun After implementation, re-export the same audit tables and compare strict_wrong_side_rows and exact_match_rows before vs after. A sampler fix is only credible if the known blockers shrink materially in the next audited sample. next_step_after_this_spec high

6. 这页的可信度

  • 高：坏样本数量、占比、mirrored pair 是否存在 —— 这些都直接来自现有 audit artifacts。
  • 中：repair rule 的设计是否正好就是最佳实现 —— 这是设计页，不是跑完后的 closure 页。
  • 低 / 暂无：修完后 breakout alpha 会不会彻底消失，或反而更稳定 —— 这必须等 A4-c 的最小重跑。
