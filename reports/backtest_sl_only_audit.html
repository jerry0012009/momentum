四、事件 + V4 信号匹配

代码位置

explore_v1_6a_second_squeeze_tpsl.py → main() (第 197-322 行)

匹配规则

  1. 对每个 symbol，找到它的所有 momentum ignition 事件
  2. 对每个事件，在事件发生后 1~48 小时的时间窗口内，找第一个 V4 信号
  3. 取该 V4 信号的 entry_price 作为本笔交易的入场价

代码：

mask = (sym_trades['ts'] > ev_ts) & (sym_trades['ts'] <= ev_ts + pd.Timedelta(hours=48))
post_trades = sym_trades.loc[mask]
first_trade = post_trades.iloc[0]  # 取第一个
entry_price = float(first_trade['entry_price'])
为什么需要两层过滤？
  • 事件（momentum ignition）= "这个币正在被市场关注"（宏观信号）
  • V4 信号（vol>3x + ret>1%）= "这个币当前 K线有异常放量上涨"（微观信号）
  • 两者叠加 = "市场关注 + 当下放量" → 更可能是真正的 momentum，而不是噪音

同小时 V4 审计：12:02 是否应直接交易 11:00-12:00 完成K线？

结论：不应放宽。保持当前 事件后 1~48h 窗口，历史 SL-only 回测为 1,951 笔、均值 +1.77%、中位数 -8.07%、胜率 16.8%、PF 1.27、收益求和 +34.50。

若允许同小时 V4，即窗口变为 事件后 0~48h，交易数增加到 2,703 笔，但均值降到 +0.88%、胜率降到 15.3%、PF 降到 1.13、收益求和降到 +23.74。

主因是新增的 752 笔同小时交易质量很差：均值 -6.06%、中位数 -8.07%、胜率 7.2%、PF 0.18、收益求和 -45.58。也就是说，12:02 直接追刚完成的事件K线，历史上不是增厚盈利，而是把事件爆发当小时的追高噪音纳入。

五、SL-Only 交易模拟（核心）

代码位置

backtest_sl_only_funding.py → sim_sl_only() (第 108-114 行)

def sim_sl_only(c, idx, px, sl_pct, timeout, fee):
    """Return (raw_return, exit_bar_idx)."""
    end = min(idx + timeout, len(c['close']))  # 超时退出的那根 K线索引
    sl_px = px * (1 - sl_pct)                   # 止损价 = 入场价 × (1 - 8%)
    for i in range(idx, end):                    # 从入场 K线开始逐根检查
        if c['low'][i] <= sl_px:                # 如果这根 K线的最低价 ≤ 止损价
            return -sl_pct, i                    # → 止损退出，亏 8%
    ret = (c['close'][end-1] - px) / px          # 超时了都没止损 → 按最后收盘价结算
    return ret, end - 1

逐行解释

步骤代码含义
1. 计算超时位置end = min(idx + timeout, len(c['close']))最多持有 96 根 K线（96 小时 = 4 天）。如果数据不够长，就到数据末尾。
2. 计算止损价sl_px = px * (1 - 0.08)入场价 × 92%。比如入场价 100，止损价 = 92。
3. 逐 K线检查for i in range(idx, end)从入场那根 K线开始，一根一根往后看。
4. 止损触发if c['low'][i] <= sl_px如果这根 K线的最低价碰到了止损价 → 立即退出。
5. 止损返回return -sl_pct, i返回 -8%（固定亏损）和退出位置。
6. 超时退出(c['close'][end-1] - px) / px96 小时内都没止损 → 按最后 K线的收盘价计算收益（可能赚也可能亏）。

为什么用 K线最低价而不是收盘价检查止损？

因为止损是"价格碰到了就触发"，不是"收盘时还在才触发"。用 low 比用 close 更真实——如果盘中最低价触及了止损线，交易所在那一刻就会执行止损，不会等到收盘。

这是保守假设（会多触发一些止损），确保回测不会高估收益。

止损 vs 超时退出的区别

退出方式条件收益计算典型结果
止损96h 内 low ≤ 入场价 × 92%固定 -8%亏 8%（每笔都一样）
超时96h 内价格从未跌破 8%(最后收盘价 - 入场价) / 入场价可能是 +50%，也可能是 -5%

六、手续费计算

代码位置

backtest_sl_only_funding.py → stats_with_funding() (第 117-137 行)

fee = 4.0 / 10000.0  # = 0.0004 = 4bps per side
nets = (1 + raw_return) × (1 - fee)² - 1

公式解释

  • raw_return = sim_sl_only 返回的价格收益（如 -0.08 或 +0.50）
  • (1 - fee)² = 开仓扣一次手续费，平仓扣一次手续费
  • (1 + raw_return) × (1 - fee)² - 1 = 扣完手续费后的净收益

数值：fee = 0.0004，(1-0.0004)² = 0.9992。每笔交易的手续费摩擦 ≈ 0.08%。

七、资金费率（Funding Rate）

代码位置

backtest_sl_only_funding.py → load_funding_cache() (第 28-55 行) + calc_funding_pnl() (第 58-72 行)

Funding 机制

Binance 永续合约每 8 小时结算一次资金费率：

  • 费率 为正 → 多头付钱给空头（做多成本）
  • 费率 为负 → 空头付钱给多头（做多收益）
def calc_funding_pnl(symbol, entry_ts, exit_ts, fc):
    """LONG: funding > 0 → longs PAY (PnL -= rate)
              funding < 0 → longs RECEIVE (PnL += |rate|)"""
    fd = fc[symbol]
    events = fd[(fd['timestamp'] >= entry_ts) & (fd['timestamp'] <= exit_ts)]
    total = events['funding_rate'].sum()
    return -float(total), len(events)  # 注意负号！
为什么要取负号？

funding_rate 的定义是"多头付给空头的比率"。所以：

  • funding_rate = +0.01%（正）→ 多头要付 0.01% → 我们的 PnL 是 -0.01%
  • funding_rate = -0.01%（负）→ 空头要付 0.01% → 我们收到 0.01% → PnL 是 +0.01%

所以 PnL = -sum(funding_rate)

Funding 数据来源

从 data/binance_funding_rate/{SYMBOL}/ 目录加载 zip 文件，每个 zip 包含 CSV，有两列：

  • calc_time — 结算时间（Unix 毫秒）
  • last_funding_rate — 该次结算的费率

Funding 何时累加？

从 入场时间到 退出时间之间所有 funding 结算事件的费率求和。

如果持仓 96 小时，理论上会有 12 次 funding 结算（96/8 = 12）。

九、牛熊过滤器

代码位置

backtest_sl_only_funding.py → main() Part 5 (过滤器循环)

逻辑

  1. 加载 BTCUSDT 的 1h K线
  2. 对每笔交易，取信号时间点的 BTC 收盘价
  3. 计算 BTC 过去 7 天（168 小时）的收益率：btc_ret_7d = (btc[now] - btc[now-168h]) / btc[now-168h]
  4. 只保留 btc_ret_7d > +5% 的交易
为什么需要？

SL-only 是纯做多策略。熊市（BTC 跌）时做多大概率止损。过滤掉熊市交易可以大幅减少亏损，同时保留牛市的高收益交易。

十一、潜在问题清单

⚠️ 已知简化/假设

  1. 入场价 = 信号 K线收盘价：实际可能有滑点，尤其放量 K线。报告中已测试 0~150bps 滑点敏感度。
  2. 止损价 = 入场价 × 92%：固定百分比止损，不考虑波动率。高波动币更容易触发。
  3. 用 K线 low 检查止损：保守假设（盘中最低价如果碰了止损线就触发），可能多触发一些止损。
  4. Funding rate = 最后一个值：Binance 每 8h 结算一次，我们用 last_funding_rate 列。实际结算时刻可能有微小偏差。
  5. 没有考虑仓位大小：回测假设每笔交易投入固定金额（等权），没有考虑 Kelly 仓位优化。
  6. 事件叠加有 look-ahead 吗？ 没有。momentum ignition 事件在 K线完成时检测（completed bar），V4 信号在事件之后才触发。
  7. trailing stop 用 HWM 有未来函数吗？ 没有。HWM（历史最高价）是入场后逐 K线更新的，只用到当前时刻的信息。

✅ 没有问题的地方

  • 数据只用已完成的 K线（不会偷看当根 K线的收盘价来决定是否入场）
  • 事件检测用 hours_from_event，信号必须在事件之后
  • 冷却机制防止同一 symbol 重复触发
  • SL-only 策略不设止盈，避免了"止盈价碰了又回来"的回测陷阱
